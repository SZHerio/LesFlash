# M3C — полноценный инвентарь

Статус: реализация завершена 23 июля 2026 года; формальная Android-приёмка ожидает закрытия [G0](G0_ANDROID_BASELINE.md).

M3C заменяет плоский счётчик `item_id → quantity` предметным агрегатом с реальными контейнерами, массой, объёмом, состоянием, стабильными ID стопок и атомарными действиями. Вкладка «Вещи» стала третьим полноценным sandbox-экраном рядом с местом и картой.

## Наблюдаемый результат

- новая попытка по-прежнему начинается без вещей и без рюкзака;
- герой различает предметы в карманах, руках, рюкзаке и внешних контейнерах;
- масса и объём рассчитываются независимо: Сила увеличивает только допустимую массу;
- карточка предмета показывает русское название, описание, состояние, фактическое место, массу, объём, количество, теги и допустимые действия;
- предмет можно выбрать, переложить, использовать, разобрать или оставить в текущей локации;
- оставленный рядом предмет виден только в своей локации и снова доступен через действие «Забрать»;
- использование и разбор заранее подтверждаются и только после этого меняют предметы, состояние и игровое время;
- переполненный контейнер возвращает сравнение и варианты восстановления; входящая находка не уничтожается;
- составная замена атомарно кладёт входящую вещь в контейнер, а вытесненную оставляет в исходном внешнем месте;
- выбранный предмет, контейнеры, состояние стопок и оставленные вещи восстанавливаются из сохранения.

## Предметы и контейнеры

Каталог [item_catalog_v1.json](../game/items/data/item_catalog_v1.json) имеет `schema_version: 1`. Определение предмета неизменяемо и отделено от сериализуемой стопки:

```text
ItemDefinition
  id, русский текст, tags
  stack_limit
  mass_grams, volume_ml
  base_value
  data-only actions

ItemStack
  stack_id
  item_id
  quantity
  condition 0…100
  metadata
  фактический контейнер
```

Каталог содержит прежние ID `cardboard_sheet`, `simple_meal`, `scrap_wire`, `recyclables` до включения строгой проверки, а также предметы первой поисковой карты. Неизвестный ID старого сохранения не удаляется: `ItemCatalog` возвращает безопасное определение «Неизвестный предмет», сохраняет исходный ID и разрешает только перемещение/выбрасывание.

Сериализуемый `InventoryState` имеет собственную версию схемы и разделён на небольшие модули:

- `inventory_schema.gd` — создание, нормализация JSON и строгая проверка;
- `inventory_metadata.gd` — рекурсивный JSON-safe контракт instance-данных;
- `inventory_query.gd` — стопки, фактические контейнеры, масса и объём;
- `inventory_mutation.gd` — добавление, удаление, split/merge и перемещение;
- `inventory_stack_writer.gd` — единая запись стопок без потери metadata;
- `inventory_replacement.gd` — составная замена без промежуточной потери;
- `inventory_transaction.gd` — clone → validate → journal → commit для `RunState`.

Вместимость каждого переносимого контейнера вычисляется как:

```text
масса = базовый предел + Сила × шаг контейнера
объём = фиксированный физический предел
```

Перегруз является явным состоянием read-model с точными числами и причиной. Новые операции не создают скрытый штраф и не телепортируют предмет; legacy-сохранение может восстановиться уже перегруженным, но ничего не теряет.

`metadata` переносится при полном и частичном move/drop/pickup/replace. Стопки объединяются только при совпадении предмета, состояния, metadata и формата количества. Вложенные metadata принимают лишь JSON-safe значения со строковыми ключами, конечными числами, безопасными целыми и ограниченной глубиной.

## Миграция сохранений

Версии подняты синхронно:

| Уровень | Было | Стало |
|---|---:|---:|
| `RunState` | 2 | 3 |
| `GameSession` | 2 | 3 |
| `RunSession` | 2 | 3 |
| envelope `RunSave` | 2 | 3 |
| envelope `RunStateSave` | 1 | 2 |

Цепочка `v1 → v2 → v3` выполняется на глубокой копии. Переход `RunState v2 → v3`:

1. строго проверяет старый словарь количеств и ровно шесть прежних навыков;
2. сортирует ID предметов и детерминированно выдаёт стабильные `stack_id`;
3. переносит предметы в видимый legacy-контейнер без потери количества; прежнее допустимое количество до `1 000 000` хранится одной ограниченной compact-стопкой на ID, а не миллионом объектов в памяти;
4. сохраняет неизвестные ID через fallback;
5. добавляет навык поиска с рангом `0`;
6. только после этого меняет версию схемы.

Реальные fixtures:

- [M3B session/envelope v2](../tests/fixtures/m3b_session_v2.json);
- [standalone RunState envelope v1](../tests/fixtures/run_state_envelope_v1.json);
- прежний [M2 envelope v1](../tests/fixtures/m2_first_day_v1.json) продолжает проходить всю цепочку.

Ошибка миграции возвращается явно, не изменяет исходный словарь и не перезаписывает файл.

## UI и архитектура

Экран [inventory_screen.tscn](../ui/screens/inventory/inventory_screen.tscn) получает только готовую read-model и испускает типизированный intent:

```text
InventoryScreen intent
→ InventoryFlowCoordinator
→ SandboxSessionAdapter
→ InventoryTransaction
→ save barrier
→ обновлённая read-model
```

Экран не импортирует `RunState` и не пишет сохранение. Сортировка, фильтры, прокрутка и раскрытая карточка являются локальным presentation-state и не сбрасываются после команды. Отдельные сцены отвечают за вместимость, предмет и адаптивный modal-sheet. Он показывает точные минуты, эффекты, результаты и условия, позволяет выбрать количество и контейнер; Android Back сначала закрывает sheet, а нижняя навигация на это время блокируется.

Путь переполнения проверен целиком: `pickup → capacity conflict → comparison/recovery → atomic replace → один save`. Неудачный preview ничего не сохраняет. Оптимистическое переключение нижней вкладки удалено: активный стиль меняется только после принятого маршрута.

Проверены `360×640` и `540×960`, масштаб текста 100%/200%, перенос длинных русских названий, touch-targets от 48 единиц и reduced motion.

Доменный набор из 12 сценариев проверяет каталог, fallback, пустой старт, независимые лимиты, split/merge, metadata, compact-миграцию, выбор, конфликт вместимости, атомарную замену, use/disassemble/drop, обе реальные миграции и точный round-trip. Headless- и desktop-render-проверки не заменяют safe area, suspend/kill/restore, Back и производительность на физическом Android-устройстве. Эти пункты остаются в открытом G0.
