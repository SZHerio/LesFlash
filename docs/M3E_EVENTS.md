# M3E — движок контекстных событий

Статус: реализован 25 июля 2026 года. Формальная приёмка на физическом Android-устройстве остаётся частью открытого [G0](G0_ANDROID_BASELINE.md).

M3E расширяет принятый [`EventContext v1`](M3D_EVENT_CONTEXT.md), а не заменяет его: форма контекста не мигрировала.

## 1. Состав

План требовал шесть вещей до массового наполнения контентом. Все шесть существуют:

| Требование | Реализация |
|---|---|
| Схема данных и версия формата | [contextual_events_v1.json](../game/events/data/contextual_events_v1.json), `schema_version: 1` |
| Валидатор ID, ссылок, условий, выходов и кулдаунов | [event_content_validator.gd](../game/events/event_content_validator.gd) |
| Просмотрщик события с произвольным состоянием героя | [event_workbench.gd](../game/events/event_workbench.gd) |
| Трассировка выбора Event Director | `EventDirector.analyze()` |
| Ускоренная симуляция распределений | [event_simulator.gd](../game/events/event_simulator.gd) |
| Стартовый набор карточек | 40 карточек, 80 ответов на шесть локаций |

## 2. Объяснимость

[`EventDirector.analyze()`](../game/events/event_director.gd) возвращает трассировку по каждой карточке каталога, а не только победителя. Для любой карточки видно:

- почему она вошла в пул либо была исключена — локация, тип источника, кулдаун или невыполненное условие с кодом и сообщением;
- базовый вес, смещение по Удаче, дельту и итоговый вес;
- результат каждой проверки условия по отдельности.

`analyze` и `preview` чисты. RNG расходует только `select`, и только тот поток, который ему передали.

## 3. Данные вместо кода

Условия ограничены словарём из шестнадцати видов ([event_condition_evaluator.gd](../game/events/event_condition_evaluator.gd)) и шести операторов. Эффекты ограничены одиннадцатью типами. Исполняемого GDScript внутри карточки нет и быть не может.

Валидатор требует у каждой карточки хотя бы один безусловный выход, поэтому достижимая карточка никогда не оставляет игрока без доступного ответа. Закрытый ответ хранит причину независимо от того, показывает ли её настройка.

## 4. Встреча внутри поиска

Это шов между M3D и M3E.

Когда риск поиска пересекает порог, [search_risk_resolver.gd](../game/search/search_risk_resolver.gd) собирает `EventContext` и просит [search_encounter_selector.gd](../game/events/search_encounter_selector.gd) выбрать карточку. Ключевые решения:

- **Карточка выбирается один раз** и сохраняется в snapshot зоны. Переоткрытие зоны, загрузка сохранения и перезапуск приложения не перебрасывают результат.
- **Seed выводится детерминированно** из seed зоны и идентификатора встречи, поэтому выбор воспроизводим и не трогает ни основной поток, ни поток зоны.
- **Встреча не создаётся, если подходящей карточки нет.** Пустой пул оставляет игрока продолжать поиск, а не запирает его перед неотвечаемым запросом.

Ответ применяется [search_encounter_command.gd](../game/events/search_encounter_command.gd) через ту же транзакционную границу, что и остальные команды поиска: клон сессии, эффекты, валидация, публикация. Повтор той же команды возвращает `duplicate_command`.

Доступность ответов пересчитывается по текущему состоянию героя, а не по состоянию на момент возникновения встречи: освободив руки, игрок открывает вариант, который был закрыт минуту назад.

После ответа риск снижается вдвое. Это не косметика: без разрядки балл навсегда оставался бы выше порога, условие срабатывания «пересечение снизу вверх» больше никогда бы не выполнилось, и шкала риска после первой встречи стала бы декоративной.

Ответившая карточка получает кулдаун и попадает в историю зоны; и то и другое передаётся в контекст следующей встречи, поэтому одна и та же ситуация не повторяется подряд.

## 5. Изменение контракта отложенных последствий

Карточки событий планируют собственные отложенные последствия. Раньше `FirstDaySession` принимала только последствия из жёстко зашитого реестра M2 `DEFERRED_PAYLOADS` с точным совпадением payload, поэтому любая карточка со своим последствием делала сессию невалидной и её ответ не фиксировался.

Контракт открыт: идентификаторы M2 сохранили прежнюю строгую проверку, а последствия версионированного контента принимаются по форме — payload должен быть непустым словарём, ключи которого преобразуются в известные показатели, деньги или знание. Движок (`EffectApplier`, `RunState`) уже был data-driven; ограничение снято только на уровне сессии первого дня.

Новая карточка теперь не требует изменения кода, чтобы запланировать своё последствие.

## 6. Границы

M3E не превращает событие в основной экран. Встреча возникает из поиска, накладывается на окружение текущего места, не получает отдельной иллюстрации и возвращает игрока туда, откуда возникла. Выход из зоны доступен и при неотвеченной встрече.

Недоступные ответы по умолчанию скрыты и показываются вместе с причиной только при включённой настройке — так же, как во всех остальных карточках игры.

Массовое производство контента не начинается: 40 карточек — это проверка формата, условий и распределений, как и предусмотрено планом.

## 7. Проверки

```bash
godot --headless --path . --script res://tests/m3e_event_director_test.gd
```

```bash
godot --headless --path . --script res://tests/m3e_search_encounter_test.gd
```

Результаты на 25 июля 2026 года: Event Director `7/7` — каталог и авторские выходы, трассировка пула, чистота предпросмотра, детерминизм выбора, влияние Удачи на долю неблагоприятных карточек на 2000 прогонах, атомарная постановка отложенного последствия и исключение по кулдауну. Встречи поиска `6/6` — постановка отвечаемой карточки, блокировка только новых решений, атомарность и идемпотентность ответа, отказ закрытого варианта, кулдаун с историей, переживание сохранения и загрузки.

Эталонный рендер экрана встречи: [docs/qa/m3d](qa/m3d).

## 8. Что не сделано

Ручная русская редактура всех 40 карточек не проводилась: тексты прошли автоматическую валидацию длины, ссылок и достижимости, но не литературную вычитку.

Проверка на физическом Android-устройстве не выполнялась.
