# G0 — Android engineering baseline

Статус: **не закрыт** на 23 июля 2026 года.

G0 подтверждает не наличие Android-настроек в проекте, а устойчивость реальной попытки на физическом устройстве. Локальные headless-тесты и эмуляция lifecycle-сигналов полезны, но не заменяют device QA.

## Что уже реализовано в приложении

- `AppShell` учитывает safe area через `DisplayServer.get_display_safe_area()`;
- системные Back, pause и close преобразуются в отдельные сигналы;
- таймер автосохранения настроен ровно на 300 секунд;
- `UiCoordinator` сохраняет попытку после подтверждённой команды, при pause, автосохранении и безопасном выходе;
- `SessionPersistence` не допускает одновременную запись, а координатор блокирует повторное применение команды;
- загрузка умеет восстанавливаться из валидных `.tmp` и `.bak` и мигрировать сохранение M2 `v1` без молчаливой перезаписи исходника;
- автоматические тесты проверяют расчёт safe area, однократную доставку Back/pause/autosave-сигналов, 250-миллисекундную защиту перехода и то, что ошибка lifecycle-сохранения не сбрасывает активную сессию.

Это инженерные предпосылки G0, а не доказательство поведения Android OS и конкретного устройства.

## Что требуется для закрытия

1. Установить совместимый Android SDK с platform-tools, build-tools и платформой, требуемой Godot 4.7.1; указать действительный SDK path в редакторе.
2. Проверить `adb version` и наличие авторизованного устройства в `adb devices`.
3. Экспортировать preset `Android Debug`, установить APK начисто и зафиксировать модель устройства, версию Android и тип системной навигации.
4. Выполнить матрицу ниже на физическом устройстве.
5. Сохранить результаты, скриншоты целевых экранов и диагностический `adb logcat` для найденных сбоев.

Пример экспорта после настройки SDK:

```powershell
godot --headless --path . --export-debug "Android Debug" build/android/bomzhara-debug.apk
adb install -r build/android/bomzhara-debug.apk
```

Если `godot` не добавлен в `PATH`, используется полный путь к установленному исполняемому файлу или экспорт из редактора.

## Обязательная device-матрица

| Проверка | Критерий | Статус |
|---|---|---|
| Портрет и вырез | фон edge-to-edge, интерактивный UI не попадает под cutout/system bars | не проверено |
| Жестовая навигация | нижняя панель не спорит с gesture inset, системный Back обрабатывается один раз | не проверено |
| Трёхкнопочная навигация | кнопки не перекрывают UI, Back сохраняет ожидаемый маршрут | не проверено |
| Сворачивание/возврат | попытка сохраняется, экран и ввод восстанавливаются без дубля команды | не проверено |
| Принудительное завершение | после `force-stop` приложение загружает последнюю подтверждённую границу | не проверено |
| Прерванная запись | валидный `.tmp`/`.bak` восстанавливается без порчи основной попытки | не проверено |
| Автосохранение | через пять минут создаётся валидное сохранение без блокировки ввода | не проверено |
| Повторный тап | одно решение не применяется дважды до и после восстановления | не проверено |
| Масштаб текста 200% | русский текст читаем, основные цели доступны и не обрезаны | не проверено |
| Физический размер UI | поля не меньше 16 dp, зоны касания не меньше 48×48 dp при реальном stretch и DPI | не проверено |
| Reduced motion | декоративное движение отключено, переходы не оставляют промежуточное состояние | не проверено |
| Производительность | нет заметных провалов кадра или зависания ввода на целевом устройстве | не проверено |

Для kill/restore следует записать до завершения процесса `flow_revision`, игровое время, деньги и показатели, затем сравнить их после продолжения. Изменения должны соответствовать ровно одной подтверждённой команде.

Отдельно необходимо измерить физический размер целей: проект пока использует виртуальный canvas `540×960`, а desktop smoke с `SubViewport(360, 640)` не воспроизводит Android DPI/stretch. Если 48 логических единиц окажутся меньше 48 dp, до закрытия G0 нужно перейти на базовый canvas 360 dp либо ввести проверенное device-aware масштабирование UI.

## Условие приёмки

G0 закрывается только после успешной физической проверки всей матрицы и сохранения отчёта с данными устройства. До этого:

- G0 остаётся открытым;
- реализация M3A считается завершённой, но формально не принятой;
- device QA нельзя заменять headless-, desktop-render- или эмуляторной проверкой.
