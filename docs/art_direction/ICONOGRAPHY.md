# Производственный стандарт иконографии

Статус: **обязателен для всех новых и перерабатываемых пиктограмм интерфейса**

Обновлено: 27 июля 2026 года

Первый производственный пакет завершён: в общем реестре находятся 35 авторских SVG. Он покрывает нижнюю навигацию, категории действий, повторяющиеся цены решений, знак ардена, типы мест текущего района, транспорт, базовые служебные команды и первые категорийные знаки инвентаря. Общая форма пакета видна на [production master sheet](../qa/iconography/iconography_master.png).

Этот документ является подробным контрактом пиктограмм. Общие требования к композиции экрана, подписям, контрасту и Android остаются в [UI/UX-стандарте](../UI_UX_STANDARD.md).

## 1. Назначение и язык формы

Пиктограмма ускоряет узнавание уже видимого смысла. Она не украшает пустое место, не заменяет русскую подпись и не сообщает скрытый шанс, исход или ещё не открытую механику.

Вся система создаётся специально для «Бомжары». Её визуальный ориентир — городская навигация, схемы служб и технические инструкции 1980-х: простая геометрия, строгий ритм и различимый силуэт. Готовые наборы, emoji, скевоморфизм, искусственная потёртость и случайное смешение стилей запрещены.

Производственный мастер строится на сетке `24×24` с `viewBox="0 0 24 24"`. Базовый штрих — `1.75`, окончания и соединения округлые. Заливка используется только для формы, которой на малом размере нужна сплошная масса, например для знака ардена. Вектор не содержит текста, встроенного растра, внешней ссылки, шрифта или собственного смыслового цвета.

Силуэт должен оставаться различимым без цвета. Если два знака различаются только оттенком, они считаются одним неудачным знаком.

## 2. Закрытая шкала размеров

Иконка рендерится только в одном из четырёх размеров:

| Размер | Назначение |
|---:|---|
| `16 dp` | компактная сумма, плотная цена решения, служебный знак и стрелка перехода |
| `20 dp` | обычная метаинформация, состояние доступности и вторичная команда |
| `24 dp` | нижняя навигация, тип места, транспорт и самостоятельная кнопка |
| `32 dp` | ведущий знак действия и крупный смысловой якорь |

Исходный SVG не дублируется ради каждого размера. Компонент `SemanticIcon` масштабирует один мастер в `16 / 20 / 24 / 32 dp`; произвольное значение нормализуется к `24 dp`. Исключение — не размер файла, а отдельная **оптическая форма**: у ардена есть компактная версия для `16 dp` и полная для `24–32 dp`.

Размер рисунка не задаёт размер касания. Интерактивная область всегда не меньше `48×48 dp`, а знак остаётся вложенным визуальным элементом.

## 3. Реестр и стабильные `icon_id`

Единственный источник соответствия ID и файла — `res://ui/icons/icon_registry.gd`. Ассеты лежат в `res://assets/icons/`, имя файла совпадает с `icon_id`.

Правила контракта:

- экран, компонент и view-model передают стабильный `StringName icon_id`, а не путь к SVG;
- локальные словари путей на отдельных экранах запрещены;
- имя описывает семантику, а не конкретный экран: `meta_time`, а не `location_clock`;
- изменение изображения при сохранённом смысле не меняет ID;
- изменение смысла требует нового ID и обновления всех производителей модели;
- неизвестный или отсутствующий ID безопасно скрывает рисунок и не создаёт пустой квадрат;
- наличие ID в реестре не открывает игроку механику: знак появляется только вместе с уже видимой сущностью.

`icon_id` является презентационным контрактом. UI не угадывает его по заголовку, русскому слову, единице измерения или результату регулярного выражения. View-model передаёт типизированный токен с готовыми `icon_id`, видимым текстом и цельной доступной фразой. Временный адаптер может сопоставить известное структурное поле вроде `time_text` с `meta_time`, но парсить значение строки (`«мин»`, `«риск»`, `«энергия»`) запрещено.

Компактные токены собирает `DecisionCostRow`; каждый `MetaToken` получает готовые `icon_id`, текст и `accessible_text`. В связном русском предложении вместо знака пишется склоняемое название: `1 арден / 2 ардена / 5 арденов`.

Карточка инвентаря получает отдельный `item_icon_id` из доменных тегов, не из русского названия. На первом проходе семантически подходящие знаки переиспользуются: еда — `action_food`, ремонт и инструмент — `action_work`, вторсырьё — `place_recycling`, ночлег — `action_shelter`, снаряжение — `nav_items`, остальные предметы — `meta_item`. Категорийный знак показывается в `32 dp`, раскрытие карточки — через `utility_chevron_right`. Собственные категории и уникальные силуэты предметов относятся ко второму проходу и не добавляются обходным локальным набором.

## 5. Слои и цвет

SVG хранится белым монохромным мастер-рисунком. Финальный цвет задаёт компонент через `self_modulate` из текущего состояния темы:

- обычный знак наследует цвет соседнего текста;
- активная вкладка, опасное действие и блокировка используют те же семантические цвета, что и их подпись или контрол;
- цвет не является единственным признаком выбора, опасности или недоступности;
- знак ардена не становится золотым автоматически;
- локальный SVG не содержит собственного зелёного, золотого, красного или сезонного варианта.

Порядок визуальных слоёв остаётся таким:

```text
базовое окружение
→ время / сезон / погода
→ наблюдаемые слои WorldState
→ след текущего занятия
→ психический post-process окружения
→ резкий UI, текст и пиктограммы
```

Психический фильтр, живописная мягкость окружения и погодные эффекты не применяются к иконкам. Сезон может менять поверхность темы, но не разрушает семантический цвет или контраст знака.

## 6. Арден

Арден имеет код `ARD` и не использует Unicode-знак. Его авторская форма — ромб, разделённый вертикальным зазором на две немного смещённые половины.

- `currency_arden_compact` имеет усиленный просвет и укрупнённые массы для `16 dp`;
- `currency_arden_full` сохраняет более вытянутую полную форму для `24–32 dp`;
- повторяющиеся короткие суммы выводятся общим компонентом `MoneyAmount`;
- если SVG не загрузился, видимый fallback — `ард.`;
- экранное чтение получает сумму целиком, например `240 арденов`, а не раздельные «240» и «значок»;
- `₽`, `$`, `€`, `£`, `¥`, `₩` и любые другие реальные денежные знаки в живом пользовательском UI запрещены.

Доменное состояние по-прежнему хранит целое количество минимальных единиц. Выбор компактной или полной формы является только решением представления и не меняет сохранение.

## 7. Доступность

- Нижняя навигация и основные действия всегда сохраняют видимую русскую подпись.
- Интерактивный родитель получает цельное программное имя; внутренний декоративный `SemanticIcon` не принимает фокус и не перехватывает касание.
- Tooltip не считается подписью на Android.
- Карта хранит доступное русское имя узла независимо от того, видна ли рядом полная подпись.
- Значение денег, времени или риска читается одной фразой, а не набором несвязанных дочерних узлов.
- Смысл не зависит только от цвета, движения или формы иконки.
- При font scale `200%` подпись переносится или растёт вместе с контейнером; соседняя иконка не обрезает текст.
- Контраст значимого знака к соседнему фону — не ниже `3:1`; обычный текст сохраняет не ниже `4.5:1`.

## 8. Запреты

В production запрещены:

- emoji, Unicode-псевдоиконки и буквенные заменители графики;
- реальные валютные знаки и названия в пользовательском UI;
- готовый сторонний набор рядом с авторскими SVG;
- PNG/WebP-копия пиктограммы, встроенный растр, `<text>` или внешний `href` внутри SVG;
- прямой путь к ассету в экране вместо стабильного `icon_id`;
- определение иконки по русскому тексту, его подстроке, окончанию или единице измерения;
- цветовая копия одного SVG для active, disabled, сезона или психики;
- знак, который сообщает скрытую проверку, будущий исход или незаработанную механику;
- декоративная иконка без функции узнавания, состояния, идентичности или причинности.

## 9. Производственный конвейер

Новый знак добавляется в следующем порядке:

1. Зафиксировать один повторяющийся смысл и точку размещения. Если знак используется один раз и не ускоряет чтение, он не нужен.
2. Выбрать стабильный ID из семейства `nav_ / action_ / meta_ / currency_ / place_ / transport_ / utility_` либо обосновать новое семейство.
3. Нарисовать авторский SVG на общей сетке `24×24`, проверить штрих и силуэт.
4. Положить файл в `assets/icons/<icon_id>.svg` и зарегистрировать его только в `IconRegistry`.
5. Передать `icon_id`, видимый русский текст и доступную фразу через типизированную модель.
6. Проверить знак в `16 / 20 / 24 / 32 dp`, без цвета и на всех семантических состояниях.
7. Проверить затронутые экраны на `360×640`, `540×960` и при font scale `200%`.
8. Обновить master sheet и пройти ручное визуальное ревью.

Второй проход расширяет эту же систему категориями предметов, героем, полярностями, событиями, профессиями и бизнесом. Новый набор или параллельный реестр для них не создаётся.

## 10. Реализация и проверка

Основные точки реализации:

| Ответственность | Файл или компонент |
|---|---|
| SVG-ассеты | `assets/icons/*.svg` |
| стабильный реестр и кеш загрузки | `ui/icons/icon_registry.gd` |
| единый рендерер размера и цвета | `ui/components/semantic_icon.*` |
| подписанная вкладка | `ui/components/nav_tab_button.*` |
| подписанная служебная кнопка | `ui/components/semantic_icon_button.*` |
| цена решения | `ui/components/meta_token.*`, `decision_cost_row.*` |
| сумма в арденах | `ui/components/money_amount.*`, `app/presentation/currency_text.gd` |
| действие локации или ответа | `ui/components/action_row.*` |
| категорийный знак предмета | `app/inventory/inventory_view_model.gd`, `ui/components/inventory_item_card.*` |
| карта и транспорт | `ui/components/city_map_canvas.gd`, `map_node_hotspot.*`, `ui/screens/city_map/` |

Автоматический контракт:

```bash
godot --headless --path . --script res://tests/ui/iconography_conformance_test.gd
```

Он закрепляет точный пакет из 35 ID, загрузку SVG, общую сетку и штрих, закрытую шкалу размеров, нативные accessibility-имена, безопасный неизвестный ID и отсутствие запрещённых glyph в современном живом UI. Legacy `ui/main.gd` и `ui/main.tscn` исключены только до их удаления в M3F; исключение не распространяется на новые экраны.

Master sheet создаётся командой:

```bash
godot --path . --script res://tests/ui/iconography_preview.gd
```

Результат сохраняется в `docs/qa/iconography/iconography_master.png`. Он дополняет, но не заменяет профильные smoke, рендеры `360×640 / 540×960 / 200%`, проверку контраста и осознанный просмотр на телефоне. Физический Android QA остаётся частью открытого G0.
