# Стандарт контента и причинности

Версия: 1.

Обновлено: 27 июля 2026 года.

Документ задаёт единый словарь для событий, NPC, навыков, знаний, отношений, репутаций и мира. Формат работающего M3E описан в [M3E_EVENTS.md](../M3E_EVENTS.md); перечисленные здесь расширения становятся задачами M3F.1 и не считаются реализованными заранее.

## 1. Главная модель

Контент отвечает на четыре разных вопроса:

| Слой | Вопрос | Пример |
|---|---|---|
| характеристика | на что герой потенциально способен | Сила `7` |
| полярность | каким способом герой привык действовать | Контроль выражен |
| навык | какую процедуру герой освоил практикой | `cargo_handling: 1` |
| знание | что конкретно герой понимает или помнит | известны расценки вторсырья |
| квалификация | имеет ли герой формальный допуск | аттестат, лицензия |
| отношение | как конкретный NPC воспринимает героя | доверие Мартина |
| репутация | что считает определённая аудитория | надёжность на пункте |
| факт мира | что объективно произошло или существует | весы откалиброваны |
| процесс мира | как развивается длительное изменение | проверка назначена |

Один слой нельзя подменять другим. Высокий Интеллект не создаёт медицинскую лицензию, Харизма не заменяет доверие после обмана, а знание о закрытой двери не делает её открытой.

## 2. Стабильные ID

Все новые ID — ASCII `lower_snake_case`. Русское название хранится отдельно. Опубликованный ID не переиспользуется для другого смысла и после удаления остаётся зарезервированным.

| Сущность | Форма | Пример |
|---|---|---|
| NPC | `npc_<name>` | `npc_viktor_koren` |
| организация | `org_<scope>_<name>` | `org_riverside_recycling` |
| группа | `group_<scope>_<name>` | `group_riverside_market_vendors` |
| работа | `job_<profession>` | `job_recycling_sorter` |
| класс задачи | `task_<domain>_<action>` | `task_recycling_move_load` |
| репутация | `rep_<audience>_<meaning>` | `rep_recycling_reliability` |
| память | `memory_<context>_<meaning>` | `memory_recycling_fixed_scale` |
| факт мира | `fact_<scope>_<meaning>` | `fact_recycling_scale_calibrated` |
| показатель | `metric_<scope>_<meaning>` | `metric_riverside_goods_supply` |
| процесс | `process_<scope>_<meaning>` | `process_recycling_inspection` |
| семейство событий | `family_<scope>_<premise>` | `family_recycling_inspection` |
| магазин | `store_<scope>_<type>` | `store_station_commission` |

Существующие ID мест, предметов, навыков, знаний и карточек сохраняются до явной миграции.

## 3. Характеристики и полярности

Четыре характеристики неизменны: `strength`, `charisma`, `intelligence`, `luck`.

Полярности не являются шкалой «плохо — хорошо»:

| ID | Левый полюс | Правый полюс | Тип |
|---|---|---|---|
| `physical_specialization` | Мощь | Выносливость | сохраняемая |
| `execution_style` | Темп | Контроль | сохраняемая |
| `influence_style` | Давление | Авторитет | сохраняемая |
| `attention_distribution` | Сосредоточение | Обзор | сохраняемая |
| `uncertainty_behavior` | Разведка | Освоение | сохраняемая |
| `decision_priority` | Возможность | Безопасность | сохраняемая |
| `relationship_investment` | Охват | Глубина | вычисляемый профиль |
| `knowledge_profile` | Специализация | Эрудиция | вычисляемый профиль |

Пользовательские смысловые диапазоны M3F:

| Значение оси | Подача |
|---:|---|
| `−5..5` | нейтрально / не сформировано |
| `±6..25` | слабый уклон к соответствующему полюсу |
| `±26..50` | заметный уклон |
| `±51..75` | выраженный полюс |
| `±76..100` | крайний полюс |

Пороги контентного доступа остаются отдельными точками `±25 / ±50 / ±75`. Контент ссылается на сторону и именованный порог, а числовую границу получает из общего balance-реестра. Карточки не размножают числа вручную. Именованные диапазоны требуют нового условия M3F.1: текущий evaluator M3E принимает только числовое `value`.

Дрейф выдаётся за выбранный способ, а не за формальный тип активности. Повторение одного безопасного действия не должно бесконечно двигать полярность. Обычное значимое решение даёт малый сдвиг, редкое рискованное решение — больший; точные числа балансируются централизованно.

## 4. Навыки

В M3F активны ровно семь существующих ID:

| ID | Минимум три применения в M3F |
|---|---|
| `city_navigation` | короткие маршруты; поиск служб; дорожные встречи |
| `cargo_handling` | рабочая задача; тяжёлая находка; помощь с переносом |
| `cooking` | безопасная еда; повышение питательности; еда для NPC |
| `repair` | предмет; укрытие; весы или пресс на работе |
| `first_aid` | собственная травма; помощь NPC; предотвращение последствия |
| `trade` | магазин; продажа вторсырья; договорённость о цене |
| `search` | сведения об объекте; безопасный подход; быстрый поиск |

Ранги: `0` — не открыт, `1` — основы, `2` — уверенное владение, `3` — мастерство.

Навык получает развитие только при наличии источника обучения и подтверждённой практики. Значимые действия дают очки освоения; игрок не может открыть неизвестный навык одними свободными очками.

Кандидаты будущего каталога, ещё не активные в runtime:

- социальные: `active_listening`, `mediation`, `customer_service`, `caregiving`;
- мобильность и безопасность: `driving`, `self_defense`, `stealth`, `outdoor_survival`, `sheltercraft`;
- ремёсла: `mechanics`, `electrical_work`, `plumbing`, `carpentry`, `welding`, `construction`, `tailoring`;
- организация: `clerical_work`, `bookkeeping`, `logistics`, `inventory_control`, `business_operations`;
- профессиональные: `clinical_care`, `legal_practice`, `teaching`, `journalism`, `digital_literacy`, `software_development`, `engineering_design`.

Кандидат становится реальным навыком только вместе минимум с тремя применениями, источником обучения, практикой и проверкой, что он не дублирует характеристику, знание или квалификацию.

## 5. Знания

M3F.1 вводит `knowledge_catalog_v1`. Типы:

- `fact` — конкретное сведение, только уровень `1`;
- `topic` — глубина понимания от `1` до `3`;
- позднее `lead` — срочная наводка со сроком действия.

Существующие знания получают каталог и сохраняют ID:

- места: `underpass_layout`, `underpass_services`, `underpass_dry_corner`, `station_layout`, `embankment_routines`, `embankment_shelter`;
- расписания и службы: `market_schedule`, `station_schedule`, `district_services`, `clinic_hours`, `clinic_support`;
- вторсырьё: `recycling_rates`, `recycling_basics`, `recycling_scale`, `metal_grades`.

Для первой работы добавляются:

- `recycling_safety`;
- `recycling_shift_routine`;
- `recycling_inspection_rules`.

Объективный факт и знание о нём различаются. Открытая калитка хранится в `WorldState`; замеченная героем калитка — в наблюдаемом read-model или знании.

Навык `trade` нельзя использовать для распознавания сплава. Для этого нужны `metal_grades`, практический контекст сортировки и при необходимости Интеллект.

## 6. Отношения, обязательства и память

Отношение хранится отдельно для каждого NPC:

| Поле | Диапазон | Смысл |
|---|---:|---|
| `trust` | `−100..100` | верит ли NPC словам и обещаниям героя |
| `respect` | `−100..100` | считает ли NPC героя компетентным и самостоятельным |
| `affinity` | `−100..100` | личная симпатия или неприязнь |
| `fear` | `0..100` | опасается ли NPC героя |

Долг и обещание — типизированное обязательство с участниками, предметом, сроком и состоянием, а не ещё одна шкала.

Память NPC содержит:

```text
memory_id
type_id
source_id
occurred_at
valence
salience
resolved
expires_at?
```

Базовые типы: `helped`, `worked_well`, `kept_promise`, `broke_promise`, `threatened`, `stole`, `caused_loss`, `shared_resource`.

Одинаковая команда не может повторно добавить память, долг или изменение отношения. Слабая бытовая память может угасать, а обещание, крупная потеря и поворотный поступок сохраняются до явного разрешения.

## 7. Репутации

Глобальных «добра», «зла» и известности нет. Репутация всегда принадлежит аудитории и имеет наблюдаемый источник.

Репутации M3F:

- `rep_recycling_reliability` — надёжность для работников пункта;
- `rep_recycling_work_quality` — качество работы для той же организации;
- `rep_market_fair_dealing` — честность сделок среди продавцов рынка.

Подозрение полиции относится к фактам закона и текущему риску, а не к абстрактной репутации. Изменение репутации требует свидетеля, записи или распространённой информации.

## 8. WorldState первого среза

Медленные показатели `0..100`:

- `metric_riverside_goods_supply`;
- `metric_riverside_job_availability`;
- `metric_riverside_sanitation`;
- `metric_riverside_safety`;
- `metric_riverside_institution_pressure`.

Первые факты:

- `fact_recycling_scale_calibrated`;
- `fact_recycling_yard_cleared`;
- `fact_recycling_press_safe`.

Первый процесс: `process_recycling_inspection`.

```text
latent
→ warning
→ preparation
→ inspection
→ approved | restricted | closed_temporarily
```

На каждой содержательной стадии меняются минимум два наблюдаемых слоя: действие, цена, работа, NPC, описание, визуальный слой места или событийный пул. Процесс не двигается от чтения интерфейса.

## 9. Первые постоянные NPC

### Мартин Гордеев — `npc_viktor_koren`

Мастер пункта вторсырья. Хочет сохранить работу пункта, ценит надёжность и безопасную работу. Появляется при найме, на сменах и в процессе проверки.

### Эмма Соколова — `npc_lidia_maren`

Медсестра Приречной поликлиники. Старается помочь в пределах времени и запасов. Появляется при первой помощи, поиске служб и последствиях рабочей травмы.

### Клара Белова — `npc_tamara_roven`

Продавщица Центрального рынка. Старается сохранить товар и постоянных покупателей. Появляется в торговле, при изменении поставок и в районных последствиях дефицита.

Каждый NPC получает расписание, стабильный портрет и речевой профиль. Характер создают цель, профессия, словарь и длина фраз, а не фонетический акцент.

## 10. Карточка события

У события есть конкретный источник: действие, поездка, работа, NPC, отложенное последствие или стадия мира. Случайность выбирает подходящую ситуацию, но не создаёт причину задним числом.

Обязательные поля будущей схемы дополняют M3E:

- `family_id`;
- `max_occurrences`;
- `npc_ids`;
- причинная категория;
- условия и мутации мира только из разрешённого словаря.

Правила текста:

- заголовок кратко называет происходящее;
- тело занимает обычно одну-три короткие фразы и описывает наблюдаемое;
- обычно достаточно двух-четырёх ответов;
- вариант начинается с действия героя;
- минимум один выход остаётся доступным;
- ответы различаются намерением и последствием, а не только наградой;
- не создаётся искусственный ответ для каждой характеристики;
- закрытая причина точна, нейтральна и не насмехается над героем;
- исход сообщает конкретное следствие, не повторяя кнопку;
- обычная карточка использует фон текущего места;
- постоянный NPC использует стабильный `npc_id` и существующий портрет.

Удача меняет вес случайной ситуации и детали неизвестного, но не стирает прямую цену уже выбранного поступка.

## 11. Причинный возврат

Значимое решение оформляется цепочкой:

```text
источник
→ решение
→ атомарная мутация героя / отношений / мира / времени
→ сохранённый факт, память, обязательство или стадия
→ наблюдаемый след
→ изменённое действие, цена, NPC или событие позднее
```

Отложенное последствие обязано хранить `source_id`. Event Director должен объяснить, какой факт, память или стадия включили карточку. Текст «ваш выбор что-то изменил» без наблюдаемого изменения не считается возвратом.

## 12. Нужное расширение M3F.1

Event Context/Director v2 должен получить условия:

- `world_fact`;
- `world_metric`;
- `world_process`;
- `npc_memory`;
- `commitment`;
- типизированное поле отношения.

Нужные эффекты:

- `change_relationship`;
- `add_npc_memory`;
- `change_reputation`;
- `set_world_fact`;
- `change_world_metric`;
- `advance_world_process`;
- `schedule_world_mutation`;
- `create_commitment`;
- `resolve_commitment`.

Все они применяются общей атомарной транзакцией и не исполняют произвольный GDScript из контента.

## 13. Валидация и редактура

- все ссылки разрешаются через каталоги;
- неизвестный или повторный ID является ошибкой;
- Event catalog/validator v2 должен принять согласованный бюджет до 100 карточек до того, как банк превысит текущий технический предел M3E `MAX_CARDS = 90`;
- у каждого знания-условия есть достижимый источник;
- текущий разрыв `embankment_shelter` исправляется до пакета M3F;
- каждый активный навык имеет источник открытия и минимум три применения;
- каждое выдаваемое знание используется минимум в двух последующих контекстах;
- каждый NPC появляется минимум в трёх контекстах и реагирует на сохранённую память;
- изменение репутации имеет аудиторию и источник;
- граф процесса не имеет недостижимых стадий и нетерминальных тупиков;
- повтор команды не дублирует деньги, предмет, память, факт или переход;
- карточка имеет достижимый выход и русский отображаемый текст;
- симуляция проверяет повторы, перекос Удачи и достижимость;
- готовая карточка проходит ручную русскую редактуру.
